# 博客评论外链管理器 — 界面描述文档

> 基于对原插件 5 张界面截图的分析整理，用于复刻开发参考。

---

## 一、插件定位

这是一款 **SEO 外链建设辅助工具**（Chrome 浏览器插件），核心功能链路为：

1. **收集**：输入一个**同行站点**的域名（如 `sprunki-game.io`，"抄作业"对象），插件到 Ahrefs / Semrush 打开该域名的外链列表页，通过**拦截 API 请求**拿到外链数据并自动翻页，再逐条用 AI 分析每个外链页面是否是"博客评论资源"（无需登录注册即可评论的博客文章页）。本质是"抄同行外链"的自动化。
2. **资源库**：所有发现的评论资源集中管理，带状态标记（可发布 / 已发布 / 失败 / 有验证码），支持筛选和导出 CSV。
3. **发布**：创建发布任务，插件自动打开目标博客页面，AI 生成评论文案并自动填入评论表单，**弹出确认框由人工审核**后点击 Submit 提交（或 Skip 跳过换下一个资源）。
4. **设置**：配置 OpenRouter API Key，并为 4 个不同环节分别指定 AI 模型。

整个插件的核心价值：**半自动化的博客评论外链群发**——AI 负责"找资源 + 填表单"，人负责"审核 + 点提交"，规避纯全自动群发的内容质量风险。

## 二、总体结构

插件由三部分界面组成：

| 界面 | 形态 | 说明 |
|------|------|------|
| 主 Popup 弹窗 | 点击浏览器工具栏图标弹出，宽约 400px、高约 460px | 包含「收集 / 发布 / 日志 / 资源库」四个顶部 Tab（注：截图一里只显示 3 个 Tab，截图四里出现 4 个，推断「日志」Tab 为动态显示或版本迭代产物） |
| 内容脚本浮层 | 注入到目标网页上的悬浮卡片 | 发布环节的"Comment Ready"人工审核确认框 |
| 设置页 | 在新标签页打开的完整 HTML 页面 | API Key 与模型配置，内容较多放不下 Popup，所以用整页 |

每个 Popup 页面底部都有统一的**页脚工具条**：`设置 | 清空数据 | 中文(下拉)`，分别是设置入口、危险操作（清空本地数据）、界面语言切换（说明插件做了 i18n 多语言，截图二里发布浮层是英文的）。

## 三、视觉设计规范（从截图提取）

### 配色（暗色主题）

| 用途 | 颜色 | 备注 |
|------|------|------|
| Popup 背景 | 极深的藏蓝黑（约 `#0d0f1a` ~ `#12141f`） | 顶部 Tab 栏区域颜色略深 |
| 卡片 / 输入框背景 | 深灰蓝（约 `#1c1f2e` / `#232736`） | 状态卡片、任务卡片、输入框 |
| 主色 / 强调色 | 亮蓝（约 `#3b82f6` / `#4a9eff`） | 激活 Tab 下划线、标题、主按钮（新建任务）、资源类型标签 |
| 成功色 | 绿色（约 `#22c55e`） | 状态徽标「可发布」、Submit 按钮、运行状态圆点、任务卡片边框 |
| 危险色 | 红色（约 `#ef4444`） | 停止收集按钮、停止/删除按钮、失败状态 |
| 正文字色 | 白 / 浅灰 | 数字大号加粗、标签小号灰 |

### 组件样式

- **顶部 Tab 导航**：等宽三/四列，文字灰白，激活项文字变亮 + 底部 2px 蓝色下划线。
- **统计数字组**：一行 4~5 列，上面是大号加粗数字，下面是灰色小字标签（如 `50 / 已发现外链`）。
- **状态指示行**：绿色圆点 + "正在xxx…"文字，表示后台任务运行中。
- **筛选 chips**：圆角胶囊按钮，可多枚并排换行，激活项为蓝底白字，其余深灰底。
- **状态徽标**：小圆角矩形，绿底 = 可发布，蓝底 = 资源类型「博客评论」。
- **按钮体系**：蓝色实心 = 主操作；绿色实心 = 确认/提交；红色实心 = 停止类危险操作；深灰 = 次要操作（Skip）。
- **卡片圆角**：约 8~12px，各区块间以留白分隔，几乎不用边框（运行中的任务卡片带绿色描边）。

## 四、各界面详细描述

### 界面 1：「收集」Tab（Popup 首页）

自上而下：

1. **Tab 栏**：`收集`（激活，蓝色下划线）｜`发布`｜`资源库`
2. **表单区**
   - 灰色小字标签：`目标域名`
   - 文本输入框：已填 `sprunki-game.io`（用户自己的站点域名）
   - 右侧红色按钮：`停止收集`（说明收集开始后按钮会从"开始收集"变为"停止收集"）
3. **实时状态卡片**（深色圆角卡片）
   - 状态行：🟢 绿点 + `正在分析外链页面...`
   - 四列统计数据：
     | 数字 | 标签 |
     |-----|------|
     | 50 | 已发现外链 |
     | 53 | 已分析 |
     | 3 | 博客评论资源 |
     | 84 | 队列中 |
4. **页脚**：`设置 | 清空数据 | 中文 ▾`

**功能说明（结合作者文章修正）**：这里的"目标域名"填的是**同行站点**（sprunki-game.io 就是一个小游戏站）。收集流程 = 插件打开 Ahrefs/Semrush 上该域名的外链列表页 → 拦截返回外链数据的 API 请求 → 自动翻页抓全 → 外链逐条入队 → 访问每个外链页面，用 AI 判断是否为"无需登录即可评论的博客文章" → 命中的存入资源库。"已发现外链 / 已分析 / 队列中" 对应拦截到的外链总量、已分析量与待处理队列。作者原话：Semrush/Ahrefs 的官方 API 很难搞，但浏览器插件可以模拟人类操作——打开指定网页、拦截 API 请求获取数据、执行翻页。

### 界面 2：发布时的网页内浮层（内容脚本）

背景是一个典型的 **WordPress 评论表单页面**（"Leave a Reply"），包含字段：

- `Comment *` 多行文本框 —— **已被插件自动填入 AI 生成的英文评论文案**（内容是对该文章观点的评论式改写，即软性评论）
- `Name *`、`Email *`、`Website *` 三个输入框 —— 均已自动填好（Website 填的是推广目标网址，这是外链的落点）
- `Save my name, email, and website in this browser...` 复选框 —— 已勾选
- `Post Comment` 提交按钮

页面右下角悬浮一个**深色圆角确认卡片**：

- 标题（蓝色）：`Comment Ready`
- 正文：*"The comment form has been filled. Please review the content and click Submit to post, or Skip to move to the next resource."*
- 两个按钮：`Skip`（深灰次要按钮）｜`Submit`（绿色主按钮）

**功能推断**：发布流程 = 打开资源页 → AI 识别表单字段并填入生成的评论 + 身份信息 + 目标网址 → 暂停，等人工审阅 → 人工点 Submit 真正提交（或 Skip 放弃该条、进入下一条）。"待审核"这个统计项对应的就是这个等待人工确认的状态。

### 界面 3：「资源库」Tab

自上而下：

1. **Tab 栏**：`收集`｜`发布`｜`资源库`（激活）
2. **筛选 chips（两行）**
   - 第一行：`全部`｜`博客评论`｜`个人主页`｜`可发布`（蓝色激活态）｜`已发布`
   - 第二行：`失败`｜`有验证码`
   - 前三个是**资源类型**筛选，后四个是**状态**筛选
3. **计数行**：`共 226 条资源`（当前筛选结果总数。226 与作者文章的实战数据吻合：程序跑一上午，分析了几个站的 841 条外链，自动筛出 226 条**无需登录注册即可发布**的资源——大部分是博客评论外链，小部分是个人主页外链，并导出 xlsx 表格分享。作者的提醒是：别纠结 841，可用资源够 226 个就行，继续爬还会更多）
4. **资源列表**（每行一个卡片式条目），每条包含：
   - 蓝色小徽标：资源类型 `博客评论`
   - 域名/路径文本（截断显示）：如 `www.moonsoap.com/...`、`www.yourcupofcake.c...`、`exsloth.com/vegan-br...`、`fashionablefoods.com...`、`www.craftberrybush.c...`、`www.wonderfulmala...`（美食博客居多）
   - 绿色状态徽标：`可发布`
   - 行内操作图标（三个）：
     - 🔗 链接图标 —— 打开/复制该资源网址
     - ↗ 箭头图标 —— 直接对该条发起发布
     - ✕ 叉号 —— 删除该条
   - （个别条目带一个小图片图标，可能是站点 favicon 或验证码截图标记）
5. **底部大按钮**：`导出 CSV`（导出全部资源清单）
6. **页脚**：同上

**状态体系推断**：`可发布`（已验证无需登录注册、有可填的评论表单且未发布）→ `已发布` → `失败`；`有验证码`是无法自动填表的特殊情况；`个人主页`是除博客评论外的另一类可留链资源类型（作者原话："大部分是博客评论外链，小部分是个人主页外链"）。

## 五、核心原理与实战经验（源自作者"哥飞"的原理讲解文章）

> 来源：栢阅社区帖子《博客评论外链自动发现和自动发布插件原理讲解》（作者：哥飞）。以下为对复刻开发有用的要点提取。

### 1. 博客评论外链是什么、为什么能自动发

- 很多博客程序延续早期互联网的开放习惯，允许**不登录不注册**直接发表评论，还能同时填自己的网站地址；评论发布后**昵称会带上指向你网站的链接**——这就是博客评论外链。
- 部分博客主不堪其扰，开启了垃圾评论拦截、强制登录、评论先审后显；但全球仍有大量**无人管理的存量博客**保留免登录评论（作者估算约几十万到几百万个），这就是自动化的空间。
- 单条这种外链权重不高，但**获取成本极低、可自动化、数量足够多**。适用于**低竞争关键词**的站点（典型案例：小游戏站——个人做够赚钱、公司做会亏本，没人砸钱买高权重外链，所以低权重外链就够拿到排名）；竞争激烈的领域（如 AI 视频站）单靠它不够，只能作为"外链域名数量看起来多"的辅助手段，吓退同行。

### 2. 自动发现原理：从同行出发滚雪球

1. Semrush / Ahrefs 能看到任意域名的外链列表，并可筛选非 SPAM 外链；
2. 两家官方 API 难搞，但**浏览器插件可以模拟人类操作**：打开指定页面、**拦截 API 请求拿返回数据**、执行翻页——这就是"收集"Tab 的数据来源；
3. 拿到同行域名的外链列表后逐条分析是否博客文章；是的话**再抓取该文章的评论列表**——评论者也是来发博客评论外链的站长，于是得到一批"都在发博客评论外链的网站"；
4. 再拿这批网站回第 1 步查它们的外链……如此**递归滚雪球**，可以滚出几百几千个小游戏站、几千几万条可发布文章（有文章评论区时间跨度超过十几年的存量资源）；
5. 发博客评论外链的不只小游戏站长，还有工具站。一句话总结：**只要关键词竞争还不激烈，博客评论外链就有效**。

### 3. 发布环节的经验

- **不同网站留链接的方式不同**（评论正文带链接 / Website 字段 / 昵称超链接等），需要让 AI 识别当前站点属于哪种方式——这正是设置页里"表单识别模型"存在的意义。
- 两种模式：**半自动**（AI 填好所有输入框，人只点提交）与**全自动**（不 review 直接发布）。

### 4. 模型与成本（为什么默认全用 Gemini Flash）

- 原作者经 Claude 推荐选用 `gemini-2.0-flash-001`：分析加测试评论共 **143 个请求只花 6 美分**；2K 请求 / 10M token 约 **$1.13**；折合**发一条外链约 $0.0000624**，近乎免费。
- 本项目沿用这一思路，设置页四个模型角色默认全是 `z-ai/glm-5.3-flash`：链接发现、分类这类高频调用场景，首选便宜快速的模型。

### 5. 浏览器插件的独特价值与扩展玩法

- 插件是很好的"中间桥梁"：能模拟人类操作网页、**直接复用浏览器里已登录的账号**（避免 AI Agent 无法登录的问题）、能拦截不支持 API 的网站的数据请求。
- 作者后续版本给插件加了 **Google Sheets 自动同步**：通过谷歌 OAuth 授权插件读写自己的一个 Sheet 表格。由此引出思路——**把 Google Sheet 当共享数据库**，浏览器插件、本地程序、服务器程序读写同一张表，实现流水线作业（例：抓推特热门 → AI 转写成小红书笔记 → 插件读笔记自动发布到账号）。

## 六、核心交互流程（串联）

```
设置 API Key
    ↓
[收集] 输入同行域名（如 sprunki-game.io）→ 开始收集
    ↓  打开 Ahrefs/Semrush 该域名外链页 → 拦截 API 请求 + 自动翻页
    ↓  外链逐条入队 → AI 分析是否"免登录可评论"的博客文章
    ↓  （博客文章的评论区也会被抓取，挖出更多同行站长网站，可回炉再收集）
[资源库] 积累"可发布"的博客评论资源（可筛选 / 删除 / 导出CSV，可同步 Google Sheets）
    ↓
[发布] 新建任务 → 圈定一批资源 → 逐条自动执行：
    打开页面 → AI 识别表单 → 生成评论并填入（评论+姓名+邮箱+网址）
    → 弹出 "Comment Ready" 浮层（半自动模式）
        ├─ 人工点 Submit → 真正提交 → 标记"已发布"
        └─ 人工点 Skip   → 跳过 → 下一条
    （全自动模式：不 review 直接发布）
    ↓
统计：总计 / 成功 / 待审核 / 失败 / 剩余
```
