# 博客评论外链管理器 — 界面描述文档

> 最初基于对原插件 5 张界面截图的分析整理，用于复刻开发参考；
> **已按本项目当前实现修订**：界面为 Chrome 侧边栏（Side Panel），**没有任何网页内悬浮窗/浮层**——原插件截图中的 "Comment Ready" 网页内浮层已由侧边栏「助手」Tab 取代；原「发布」任务队列 Tab 也已移除，发布由「助手」Tab 对当前激活标签页逐步驱动。

---

## 一、插件定位

这是一款 **SEO 外链建设辅助工具**（Chrome 浏览器插件），核心功能链路为：

1. **收集**：输入一个**同行站点**的域名，插件复用用户已打开的 Semrush 工具页（经 dash.3ue.co 共享面板），**纯 DOM 抓取**外链表格（不构造/不重放任何接口请求），点页面「下一页」按钮自动翻页；随后逐条访问外链页面，用**纯规则判定**（不经 AI）分析是否是"博客评论资源"（有评论表单且无需登录）。本质是"抄同行外链"。
2. **资源库**：所有命中的评论资源集中管理，带状态标记（可发布 / 已发布 / 有验证码）与启停标记（enabled），支持筛选和导出 CSV。
3. **发布**：**无后台任务队列**。由侧边栏「助手」Tab 驱动：把当前激活标签页导航到资源页面 → AI 生成标题摘要与评论 → AI 识别表单 → 自动填表 → 人工在**侧边栏**里检查后点 Submit / Skip（Submit 成功写 published 表防重复，可补备注；也可「标记为无效资源」停用该条）。
4. **设置**：配置 OpenRouter API Key，为 4 个不同环节分别指定 AI 模型，以及发布身份、语言等。

整个插件的核心价值：**半自动化的博客评论外链发布**——AI 负责"填摘要 + 填表单"，人负责"审核 + 点提交"，规避纯全自动群发的内容质量风险。

---

## 二、总体结构

插件界面只有两部分：

| 界面 | 形态 | 说明 |
|------|------|------|
| 侧边栏（Side Panel） | 点击工具栏图标打开的 Chrome 侧边栏面板 | 包含「收集 / 助手 / 日志 / 资源库」四个顶部 Tab，是全部日常操作的界面 |
| 设置页 | 在新标签页打开的完整 HTML 页面 | API Key、四模型、发布身份、语言、AI 超时等配置，内容较多放不下侧边栏，所以用整页 |

**没有 Popup 弹窗，也没有注入到目标网页上的任何浮层 DOM**——内容脚本（analyzer/publisher）只做无 UI 的页面读取与表单操作，所有确认、审核、提示都发生在侧边栏里。

侧边栏底部有统一的**页脚工具条**：`设置 | 清空数据 | 重载插件`——分别是设置入口、危险操作（清空本地数据）、开发者热重载（`chrome.runtime.reload()`）。

## 三、视觉设计规范（暗色主题，沿用原插件截图风格）

### 配色（暗色主题）

| 用途 | 颜色 | 备注 |
|------|------|------|
| 面板背景 | 极深的藏蓝黑（约 `#0d0f1a` ~ `#12141f`） | 顶部 Tab 栏区域颜色略深 |
| 卡片 / 输入框背景 | 深灰蓝（约 `#1c1f2e` / `#232736`） | 状态卡片、输入框 |
| 主色 / 强调色 | 亮蓝（约 `#3b82f6` / `#4a9eff`） | 激活 Tab 下划线、标题、主按钮、资源类型标签 |
| 成功色 | 绿色（约 `#22c55e`） | 状态徽标「可发布」、Submit 按钮、运行状态圆点 |
| 危险色 | 红色（约 `#ef4444`） | 停止按钮、清空数据、失败状态 |
| 正文字色 | 白 / 浅灰 | 数字大号加粗、标签小号灰 |

### 组件样式

- **顶部 Tab 导航**：等宽四列，文字灰白，激活项文字变亮 + 底部 2px 蓝色下划线。
- **统计数字组**：一行 4 列，上面是大号加粗数字，下面是灰色小字标签（如 `50 / 已发现外链`）。
- **状态指示行**：圆点 + 状态文字（绿色 = 待确认/运行中，灰 = 空闲）。
- **筛选 chips**：圆角胶囊按钮，可多枚并排换行，激活项为蓝底白字，其余深灰底。
- **状态徽标**：小圆角矩形，绿底 = 可发布，蓝底 = 资源类型「博客评论」。
- **按钮体系**：蓝色实心 = 主操作；绿色实心 = 确认/提交（Submit）；描边 = 次要操作；深灰 ghost = Skip 等；红色 = 停止/清空类危险操作。
- **卡片圆角**：约 8~12px，各区块间以留白分隔。

## 四、各界面详细描述（按当前实现）

### 界面 1：「收集」Tab（侧边栏首页）

自上而下：

1. **Tab 栏**：`收集`（激活）｜`助手`｜`日志`｜`资源库`
2. **表单区**
   - 灰色小字标签：`目标域名`（同行站点）
   - 数据源选择（Semrush 已联调「面板模式」/ Ahrefs 占位「直连模式」待联调）
   - 翻页随机间隔（最小/最大毫秒）、「页面 AS ≥」下限筛选（低于阈值的来源行不入库，默认 25）
   - `开始收集` / `开始分析` 按钮（运行中变为 `停止收集` / `停止分析`）
3. **实时状态卡片**（深色圆角卡片）
   - 状态行：🟢 绿点 + `正在抓取外链…` / `正在分析外链页面…`
   - 四列统计数据（跨轮次累积口径，与 IndexedDB 表对账）：
     | 数字 | 标签 |
     |-----|------|
     | 50 | 已发现外链（backlinks 条数） |
     | 53 | 已分析（analysis 条数） |
     | 3 | 博客评论资源（ready/captcha 条数，与资源库筛选一致） |
     | 84 | 队列中（已发现未分析的） |
   - `导出 CSV` 按钮（按目标域名从 IndexedDB 导出外链清单，带 BOM）
4. **页脚**：`设置 | 清空数据 | 重载插件`

**功能说明**：收集流程 = 用户先在 dash.3ue.co 打开 Semrush 工具并停留在报告页 → 插件校验当前标签、取 URL 里的 `__gmitm` 令牌 → 纯 DOM 抓取 `a[data-test-source-url]` 行（只保留「博客」标签来源）→ 点页面「下一页」按钮自动翻页（随机间隔）→ 外链逐条入档 → 「开始分析」逐条访问页面，纯规则判定：要求登录 → 跳过；无评论表单 → 不入库；有评论表单 → 命中入资源库（检测到验证码标记 captcha）。

---

### 界面 2：「助手」Tab（发布主操作台，取代原网页内浮层）

> 原插件的发布确认发生在目标网页右下角的 "Comment Ready" 浮层上；**本项目已取消一切浮层**，发布全程在侧边栏「助手」Tab 内完成，操作对象 = 浏览器**当前激活的标签页**（仅 http/https 可注入）。

自上而下：

1. **「当前任务」配置区**（可折叠）：任务名称 / 目标地址 / 网站介绍 / 主关键词，字段失焦即存；可从模板下拉选择填充并保存（模板存 IndexedDB `templates` 表，同名覆盖即编辑，可删除）。
2. **当前资源行**：显示当前激活标签页 URL；按钮 `换一个（在当前标签页打开未发布资源）`（把激活标签页导航到资源库中未发布过的下一条：ready 优先于 captcha，同档按命中时间新→旧）、`定位同行网站` + 右侧域名输入框（绑定资源时自动回填该资源来自的同行域名，可手改；在页面里定位指向输入框域名的链接，结果提示在状态行）。
3. **状态卡片**：
   - 状态行：圆点 + 状态文字（如「评论表单已自动填好。请检查内容后点击 Submit…」）。
   - **步骤按钮行**（互不依赖、可任意顺序、可重复触发）：`获取标题与摘要` → `AI 生成评论` → `AI 识别评论表单` → `自动填写表单`（需评论已生成）。
   - **字段区**（仅绑定当前页面时展示）：标题 / 摘要（含文章语言）/ 评论内容 / 评论译文 / 昵称 / 邮箱，每项带 **⧉ 图标复制按钮**（点击变 ✓ 表示已复制）。评论内嵌链接用 `{{LINK:锚文本}}` 占位符由后台替换为 `<a>`；评论语言跟随文章语言，另附译文仅供参考、不填表。
   - **决策按钮行**：`Skip`（深灰）｜`Submit`（绿色）——仅「表单已填好、待人工确认」（awaiting_review）时解锁。
   - Submit 成功后出现**备注行**：文本框（默认「需要审核」）+ `备注` 按钮，把内容写入 published 表对应记录的 `comment` 字段。
   - `标记为无效资源` 按钮（绑定页面即可用）：把 IndexedDB analysis 表中该 URL 的记录 `enabled` 置为 false（数据保留，资源库中停用）。
4. **页脚**：同上。

**发布流程**：资源库点 ↗（或助手页「换一个」）把当前标签页导航到资源页 → 后台自动绑定该页面（全框架注入 + 纯规则页面检测：验证码/登录/表单，只提示不阻断）→ 人工逐步触发 AI 步骤（摘要 → 评论 → 识别表单 → 填表）→ 检查后 Submit / Skip。Submit 成功写 published 表（按 [url, targetUrl] 防重复）并作废已提交评论（强制重新生成防误重复提交）；Skip 仅清理页面标记，停在当前页可继续操作或「换一个」。已发布过的 [url, targetUrl] 绑定时会在状态行提示，避免重复评论。

---

### 界面 3：「资源库」Tab

自上而下：

1. **筛选 chips（两行）**
   - 类型：`全部`｜`博客评论`（收集阶段的 Semrush「博客」标签保证来源类型）
   - 状态：`可发布`（ready，蓝色激活态）｜`有验证码`（captcha）｜`已发布`｜`已停用`（enabled=false）
2. **计数行**：`共 N 条资源`（当前筛选结果总数）
3. **资源列表**（每行一个卡片式条目），每条包含：
   - 蓝色小徽标：资源类型 `博客评论`
   - 域名/路径文本（截断显示）
   - 状态徽标：`可发布` / `有验证码` / `已发布` / `已停用`
   - 行内操作：
     - 🔗 打开/复制资源网址
     - ↗ 把当前激活标签页导航到该资源（进入助手页发布流程）
     - 启停开关（改 analysis 表 enabled 标记，数据保留）
4. **底部大按钮**：`导出 CSV`
5. **页脚**：同上

**状态体系**：`可发布`（ready：有评论表单、未发布）→ `已发布`（published 表有记录）；`有验证码`（captcha：发布时检测到验证码，也算命中资源）；`已停用`（enabled=false，含助手页「标记为无效资源」的条目）。

### 界面 4：「日志」Tab

运行日志时间线列表（每条含来源 collect/publish/ai/system、时间、URL、文案、级别），最新在前；右上角有「记录日志」开关（关闭后日志直接丢弃）与「一键复制」。设置页可配置日志条数上限。

### 界面 5：设置页（整页，新标签页打开）

页面标题：`博客评论外链管理器 - 设置`

1. **OpenRouter API Key**：密码输入框 + `测试连接`（Key 只存 chrome.storage.local，快照只暴露 hasKey 布尔值，不回传本体）。
2. **模型配置**（四个角色独立配置，默认 `z-ai/glm-5.3-flash`）：

   | 配置角色 | 用途 |
   |--------|------|
   | 链接分类模型 | 判断外链页面是否属于博客/可评论资源（兼作文章摘要总结） |
   | 表单识别模型 | 识别评论表单的各字段（昵称/邮箱/网址/正文） |
   | 评论生成模型 | 根据文章摘要生成相关的原创评论文案 |
   | 链接发现模型 | 预留的候选外链发现角色 |

3. **发布身份**：昵称 / 邮箱 / 网址（网址兼作目标地址缺省值）。
4. **语言**：界面语言（中/英 i18n）、标题与摘要输出语言（评论语言跟随文章语言，译文跟随摘要语言）。
5. **AI 超时**：单次请求超时秒数（默认 20s，5-300s 收敛；超时主动中止，另有面板侧看门狗兜底）。
6. **日志条数上限** 等。

**设置的唯一写入口是后台 `setSettings` 消息**（options 页不直接写 storage，避免被后台内存态覆盖）。

## 五、核心原理与实战经验（源自作者"哥飞"的原理讲解文章）

> 来源：栢阅社区帖子《博客评论外链自动发现和自动发布插件原理讲解》（作者：哥飞）。以下为对开发有用的要点提取。

### 1. 博客评论外链是什么、为什么能发

- 很多博客程序延续早期互联网的开放习惯，允许**不登录不注册**直接发表评论，还能同时填自己的网站地址；评论发布后**昵称会带上指向你网站的链接**——这就是博客评论外链。
- 部分博客主开启了垃圾评论拦截、强制登录、评论先审后显；但全球仍有大量**无人管理的存量博客**保留免登录评论（作者估算约几十万到几百万个），这就是自动化的空间。
- 单条这种外链权重不高，但**获取成本极低、可自动化、数量足够多**。适用于**低竞争关键词**的站点（典型案例：小游戏站）；竞争激烈的领域单靠它不够，只能作为"外链域名数量看起来多"的辅助手段。

### 2. 发现原理：从同行出发滚雪球

1. Semrush / Ahrefs 能看到任意域名的外链列表，并可筛选非 SPAM 外链；
2. 两家官方 API 难搞，本项目采取更保守的**面板模式**：复用用户已打开的 Semrush 报告页，纯 DOM 读取表格 + 点击页面已有按钮翻页，**不拦截、不重放接口请求**；
3. 拿到同行域名的外链列表后逐条分析是否博客文章（本项目的分析是纯规则判定，不经 AI）；原插件还会抓取文章评论列表挖出更多同行站长网站递归滚雪球（本项目未实现，作为扩展方向）；
4. 发博客评论外链的不只小游戏站长，还有工具站。一句话总结：**只要关键词竞争还不激烈，博客评论外链就有效**。

### 3. 发布环节的经验

- **不同网站留链接的方式不同**（评论正文带链接 / Website 字段 / 昵称超链接等），需要识别当前站点属于哪种方式——本项目由 AI 表单识别给出 `linkMethod`，评论正文带链接时用 `{{LINK:锚文本}}` 占位符生成 `<a>`。
- 本项目只做**半自动**：AI 填好表单，人检查后在侧边栏点 Submit；没有全自动直接发布模式（规避质量风险）。

### 4. 模型与成本

- 原作者选用 Gemini Flash：分析加测试评论共 143 个请求只花 6 美分，折合发一条外链近乎免费。
- 本项目默认四个角色全用 `z-ai/glm-5.3-flash`：高频调用场景首选便宜快速的模型；所有请求带低推理力度，避免思考模型把 max_tokens 吃光。

### 5. 浏览器插件的独特价值

- 插件能模拟人类操作网页、**直接复用浏览器里已登录的账号**、能读取不支持 API 的网站页面数据。
- 原作者后续版本加了 Google Sheets 自动同步（本项目未实现，作为扩展方向）：把 Sheet 当共享数据库，插件、本地程序、服务器程序流水线协作。

## 六、核心交互流程（当前实现）

```
设置页填 API Key
    ↓
[收集] 输入同行域名（如 sprunki-game.io）→ 打开 dash.3ue.co 的 Semrush 报告页 → 开始收集
    ↓  纯 DOM 抓取外链表格（只留「博客」标签）→ 点「下一页」自动翻页（随机间隔）
    ↓  外链逐条入 backlinks 表（「页面 AS ≥」过滤低价值行）
[收集·开始分析] 逐条访问外链页面，纯规则判定：
    要求登录 → 跳过；无评论表单 → 不入库；有表单 → 入 analysis 表（ready；发现验证码 → captcha）
    ↓
[资源库] 筛选/启停/导出 CSV；点 ↗ 或到助手页「换一个」
    ↓
[助手] 当前标签页导航到资源页 → 自动绑定（注入 + 规则检测：验证码/登录/表单提示）
    获取标题与摘要 → AI 生成评论（内嵌 {{LINK:锚文本}}，附译文）→ AI 识别表单 → 自动填写表单
    ↓  awaiting_review（表单已填好，等人工确认——确认界面在侧边栏，不在网页上）
    ├─ Submit → 真正提交 → 写 published 表 → 备注行（默认「需要审核」）可补 comment
    ├─ Skip → 清理页面标记，留在当前页
    └─ 标记为无效资源 → analysis.enabled=false（资源库停用，数据保留）
```
